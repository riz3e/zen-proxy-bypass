# Подресурсы страницы из списка обхода тоже идут напрямую

## Context

Сейчас direct получают только запросы, чей **собственный** хост есть в списке обхода (`background.js:20-26`). Внешние источники, которые такая страница подключает (скрипты, стили, картинки, API-вызовы на чужие домены), продолжают идти через прокси — и на сайтах, которые работают только напрямую (отбрасывают IP прокси-выхода), эти запросы ломаются.

Нужно: если ресурс загружается **в документ**, чей хост есть в списке обхода, он тоже идёт напрямую. По решению пользователя поведение **всегда включено**, без новой настройки (никаких изменений в DEFAULTS/popup/options).

## Изменения

### 1. `background.js` — `onRequest` (строки 19–26)

Вынести повторяемый `cfg.bypass.some(...)` в локальный хелпер и добавить проверку `details.documentUrl`:

```js
// A host is direct if it is on the bypass list.
function matchesBypass(host) {
  return cfg.bypass.some((e) => matchesEntry(host, e));
}

// browser.proxy.onRequest listener: decides the fate of every request.
function onRequest(details) {
  const host = hostOf(details.url);
  if (host && (isAlwaysDirect(host) || matchesBypass(host))) {
    return [{ type: "direct" }];
  }
  // A subresource loaded into a document whose host is on the bypass list
  // goes direct too. Navigations ("main_frame") are excluded: a link click
  // from a bypassed page to another site must stay proxied.
  if (details.type !== "main_frame") {
    const docHost = hostOf(details.documentUrl);
    if (docHost && matchesBypass(docHost)) {
      return [{ type: "direct" }];
    }
  }
  return [proxyConfig()];
}
```

Семантика (проверено по MDN: в Firefox `proxy.onRequest` даёт `documentUrl` — «URL of the page into which the requested resource will be loaded» — и `type`):
- `documentUrl` покрывает ресурсы самой страницы и same-origin iframe'ов (их documentUrl — хост страницы).
- Ресурсы **внутри** стороннего iframe остаются через прокси: их `documentUrl` — хост iframe, не страницы (безопасная сторона инварианта «неизвестный домен — через прокси»).
- Нет `documentUrl` / он невалиден (service worker, `about:blank`) → `hostOf` вернёт `null` → прокси.
- Guard `main_frame` исключает навигации: клик по ссылке с обходной страницы на чужой сайт остаётся через прокси.
- Переиспользуются существующие `hostOf`, `matchesEntry`, `isAlwaysDirect` из `common.js` без изменений.

### 2. `AGENTS.md` — один пункт в «Key decisions (and why)»

Зафиксировать решение (English, в стиле файла): a bypass-list entry means "the page works direct" — subresources loaded into that page (`documentUrl` host) go direct too; `main_frame` navigations stay proxied.

- `manifest.json`: `1.0.1` → `1.0.2`.
- Собрать `proxy-exclude-1.0.2.xpi` обычным `zip` из корня репо (сохраняет внутренние пути: `zip -X proxy-exclude-1.0.2.xpi manifest.json common.js background.js popup.html popup.js options.html options.js style.css icons/*.png`), как требует AGENTS.md; версию и имя .xpi менять только вместе.
